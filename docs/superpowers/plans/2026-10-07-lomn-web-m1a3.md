# LOMN Web M1a-3 (Faithful states) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render areas with the original game's own Direct3D 8 fixed-function state. That covers:
- render modes;
- lighting, which is off for areas in normal play;
- two-pass alpha with the TFACTOR leak;
- fog from `Base.osi`;
- filters, texture transforms, draw order and clears.

Each piece is checked by:
- a state log equal to an independent oracle derived from the decompiled code (A9);
- vertex-colour use on the null backend (A10);
- the user's screenshot comparison (A8 final).

**Architecture:**
- **rhi additions:** front face, depth bias, and out-of-frame draws rejected in both backends.
- **`lomn_d3d`:** a D3D8 state shim plus an FFP compiler (an uber-shader with a 1,024-byte uniform block per draw).
- **`lomn_sage` additions:** a bounded OSI script reader and a `textures.slb` parser.
- **Area loader additions:** materials, lights, script fog and level type.
- **`SageFrame`:** replays the original frame (render-mode pushes, DrawX passes, SortIt) into the shim.
- **`lomn_view` and the datacheck:** extended, including a wasm32 build under Node.

**Tech Stack:** as M0–M1a-2.

## Global Constraints

- **M0–M1a-2 constraints still hold.**
  - Never commit game data, renders or exe-derived code (names, counts, addresses and short formulas are allowed).
  - Never run the game's `.exe`/`.dll`.
  - Every external command has a timeout, and there are no fixed sleeps.
  - Commits use the task-scoped files and the co-author trailer as a second `-m`.
- **The tasks are a chain, not independent.** Apply them in order T1→T7; each one is green only on top of the previous ones.
- **rhi stays additive.** Valid M0/M1a-2 calls log byte-identical text. New fields default to the old behaviour: `front_face` CCW and `depth_bias` 0.
- **Uniform rule (rhi.h):** within one frame a uniform range is written at most once, and every draw has its own dynamic offset.
- **Untrusted input:** OSI caps come from measured real maxima (REF3 `logs/osi-maxima.json`). Hitting a cap is an error and leaves no partial state.
- **Determinism:** the A7 call log and the A9 state log are identical across runs and between native and wasm32. That includes real-area logs, through the new Node disk FS.
- **A7 is regenerated exactly once**, in T5, from REF3's file. A9 is introduced in T5.
- **GPU pixel tolerance at alpha-tested edges:** ≤ 16 px at ≤ 8 levels per channel for real scenes; synthetic probes are ±2.
- **User-eyeball gates:**
  - G1: the ghut net drawn as a TFACTOR-leak translucent sheet.
  - G2: vllg's pale-pink fog, 0xFFF9DCF9.
  - G3: out-of-range vertex colours clamped rather than wrapped.
  - G4: FOV 72° and near 0.01.

  These are A8 questions for the user. No task may "fix" them on its own judgement.

## Review Focus

1. **The new untrusted parser (OSI).** Every attacker-controlled accumulation is capped (calls, arguments, string bytes, instructions, stack depth), with crafted probes on both targets. Pinned by `test_sage_osi.cpp`, the `osi_probe` ctest (native and wasm32) and `make fuzz-osi` (T3, T7).
2. **Fidelity of the replayed state sequence** (render modes 0x14634/…, LIGHTING off, DrawX passes, the ALPHAARG2 TFACTOR leak, `SetFog` around plnt/tre1, SortIt). Pinned by the A9 state log equal to the independent `a9_oracle.py` on synthetic data and, under `LOMN_DATA`, on vllg/ghut/crss (T5).
3. **FFP math errors shared by the shader and its CPU reference.** Pinned by `ffp_oracle.py`, written independently from the DirectX 8.1 documentation and run on the `gpu_ffp` cases plus 4,000 samples (T2).
4. **M0/M1a-2 regression through rhi changes.** Pinned by the unchanged M0 GPU, determinism and smoke tests, plus the new winding, depth-bias and out-of-frame probes in `test_gpu_mesh.cpp` (T1).
5. **Native ≠ wasm32 on real data.** Pinned by `make datacheck-wasm` (native and wasm32 null and state logs equal for real areas) and the oracle run on wasm32 (T6).
