# LOMN Web M1b (Browser viewer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any area of the game renders in Chromium from the player's own files, read locally, with nothing uploaded. The browser render is pixel-identical to the native renderer, with a free-fly camera and an honest `?hud=1` overlay.

**Architecture:**
- **rhi:** `destroy_*` follows a dependency rule: destroying an object a live bind group uses is rejected, not cascaded. GPU memory is destroyed explicitly, deferred to `end_frame()` inside an open frame. Also added: `live_objects()`, a Depth32Float depth buffer for the canvas surface, `resize`, and a device-lost handler.
- **`AreaRenderer::release`:** owns and frees everything it created.
- **`PrefetchFileSystem`:** an index of all files plus resident byte ranges, loaded in miss-driven rounds. The boot set is pinned before `main()`, and ranges are released on area switch.
- **Free-fly camera:** in C++, fed by JS input.
- **BYO page:**
  - Chromium: `showDirectoryPicker`, with the handle kept in IndexedDB.
  - Other browsers: an OPFS worker copy.
  - Validation: the exe SHA plus a fingerprint of the blk tables.
- **Viewer page:** HUD with measured display-rate reconciliation, CSP, and content-hashed assets.
- **Tests:**
  - a synthetic A13 test in `make check`;
  - a real-data A13 test whenever `LOMN_DATA` is set.

**Tech Stack:** as M0–M1a-3, plus browser JS modules (no framework), Playwright 1.63 Chromium channel, OPFS, IndexedDB.

## Global Constraints
- **Branch `m1b-viewer` from `af5a77c`,** in worktree `../lomn-web-m1b`. Print `git rev-parse HEAD` at the start of every task.
  - The REF copies are FULL files. They are valid only on top of BASE `af5a77c` plus the earlier M1b tasks.
  - Never copy them over a tree containing M1a-4 changes.
  - The controller merges M1a-4 and M1b after both are reviewed. That merge is its own step, re-runs both suites, and keeps M1a-4's area.cpp changes (cave lighting, overflow guards).
- **The tasks are a chain:** T1→T2→T3→T4→T5a→T5b→T6→T7, sequential.
  - REF's lane note (T3, T4 and T5a are independent) is overruled. T3's `area.cpp` is full and includes T2's code, and every task edits `engine/CMakeLists.txt`.
  - The whole chain builds in about 6 min, so parallel lanes would save almost nothing and risk mixing tasks.
- **All earlier constraints hold.**
  - Never commit game data, renders, screenshots or exe-derived code.
  - Never run the game's `.exe`/`.dll`.
  - rhi stays additive: M0–M1a-3 calls log byte-identical text.
  - Native and wasm32 logs stay identical.
  - Untrusted input is bounded, and a rejection leaves no partial state.
- **Long work runs detached.** No tool call blocks more than about 2 minutes in the foreground.
  - `make test-*`, `make check` and Playwright run with Bash `run_in_background`, `CMAKE_BUILD_PARALLEL_LEVEL=4`, and a command that exits on success and on failure.
  - The host is shared.
- **No deploy, no third-party network calls.** Deploy (1.9) needs the owner's explicit yes.
- **Pixel gate:** tolerance 0 between native and browser on the same machine, always reported beside its null (0) and its positive control (fog off ≥ 100,000 px). Other GPUs follow the procedure in `web/tests/README.md`.
- **Owner-only checks, which no task may close on its own judgement:**
  - the real `showDirectoryPicker` gesture and permission re-prompt;
  - mouse look and pointer lock on a real screen;
  - Safari and Firefox;
  - the GPU memory plateau in Activity Monitor over 30 vllg↔frnt switches;
  - the spec 1.8 eyeball and fps acceptance;
  - G1–G4;
  - the canonical-build data fingerprint and the REBUILT exe hash.

## Review Focus
1. **GPU objects freed early or late.** Probe 2 must still render after the deferred Destroy. Real switches must keep GPU objects flat (29 textures / 10.7 MB over 30 vllg↔frnt). Pinned by `test_gpu_destroy` (T1/T2) and the a13_real I1 probe (T6).
2. **A read outside the prefetched set that hangs, or changes engine behaviour versus native.** Pinned by `test_prefetch_fs` (miss → recorded Io error; round cap), browser reads equal to the native `--manifest` on 5 areas, and the 122-area sweep with at most 8 rounds measured, cap 12, 0 B over-fetch (T3, T6).
3. **Hostile or odd user folders.**
   - Path traversal, over-long UTF-8 names and case duplicates.
   - A tampered IndexedDB or OPFS manifest, a partial copy, a moved folder.
   - Verdicts: an unknown exe is rejected; unknown tables are soft-accepted with a warning.

   Pinned by `unit_test.mjs`/`unit_r2_test.mjs` (T5a), byo_synthetic (T5b) and JS fingerprint == Python fingerprint (`test_byo_fingerprint.py`, T5a).
4. **Silent failure on the page.** A GPU-process crash or a moved folder must not leave a frozen `area-ready` page. HUD fps must not reconcile a dropping run as clean. Pinned by the red-first sections of byo_synthetic (CDP `crashGpuProcess`, deleted folder, `?debug_spin`) in T5b.
5. **Game data leaving the machine.** Every request must be in `asset-manifest.json` and same-origin, and the CSP must block foreign fetches. Pinned by the network check with its firing control in byo_synthetic/a13_real (T5b/T6).
