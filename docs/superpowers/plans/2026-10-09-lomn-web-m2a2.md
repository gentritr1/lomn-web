# M2a-2 — Native framework, `Setup` to the first `Process`, `lomn_view --script`: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Base.osi` runs `Setup` and N `Process` frames headless, natively and as wasm32, behind `lomn_view --script 1`. Natives are **real** wherever their result can change what the script does.
- Every native the run reaches is tier 1 (implemented and cited) or tier 2 (a stub that a taint pass proves harmless).
- An independent Python model of every tier-1 native agrees with the C++ byte for byte on the trace.

**Architecture:** M2a-1's VM is unchanged except for small additions. Around it goes a native framework:
- a game-object model that mirrors `CreateVariant(T*)` and the engine's reference counts (handles, never pointers, D7);
- a `HostContext` that owns the state of each subsystem (area director, saver, ...);
- a `ScriptHost` that owns the `ScProcessManager` frame loop, now shared by `lomn_osi_run` and `lomn_view`;
- natives bound by group, each citing its wrapper body and the method it calls.

The Python oracle gets its own framework and its own native models, written by different agents from the same citations, plus the A10 taint pass. Tiers and decided defaults live in one committed overrides file that `tools/osi/registry.py` merges, so `data/osi/natives.json` stays generated.

**Tech stack:**
- C++17 (CMake, doctest);
- emscripten wasm32 under node 20;
- Python 3 (stdlib only for the oracle);
- GNU make.

Read as data only: `objdump --x86-asm-syntax=intel` on the exe and on the Beta 1.5.0 mod DLLs, and the Ghidra corpus `gen/decomp`.

## Review focus (failure modes no task's own tests cover, and the test that now pins each)

1. **A shared misreading of a native.** C++ and Python read the same decomp line the same wrong way: byte order, an initial reference count, a field offset, a default value. Agreement then proves only consistency. LOMN has already paid for byte-swapped FourCC constants once.
   - **Pin (Tasks 7–9, each side):** one `asm-pin` test per implemented native. Its expected value is computed by hand from `objdump` bytes and cites the instruction address; each side writes its own. Example: `stringtoidentifier("frnt")` → **0x66726e74**, from the shift immediates at 0x5fb093/0x5fb09e/0x5fb0a9/0x5fb0b2 (first character in the high byte).
   - The Opus reviewer of each side re-derives 3 pins at random from the asm without reading either implementation, and names any pin that was taken from the decomp alone.
2. **Engine reference counts and `F g` timing.** A game object the engine still holds is freed when the script drops its last variant, or one the engine releases is never freed. This shows up only as a trace difference many frames later, or never.
   - **Pin (Task 2b → Tasks 3 and 4):** three conformance programs using the new declarative field `{"game": "<Class>", "engine_refs": k}`. The heap stores total = k (engine) + 1 (the returned variant).
     - `n-game-engine-ref-survives`: k = 1, two `Dup`s, three `Pop`s → no `F g`, and `heap.live.g` = 1.
     - `n-game-engine-ref-zero`: k = 0, today's `new_game(type)` behaviour → one `F g` at the last `Pop`.
     - `n-game-identity`: the same object returned twice → one `A g`, and 0x60 gives 1.
   - Both runners must pass all three.
3. **The replay hides a native divergence.** The A9 replay leg compares VM semantics only, so a C++ native that is wrong in the same way as the replayed log would pass.
   - **Pin (Task 10):** the A9 run also compares the C++ digest's `D` lines against Python running **its own models** (`--real-natives`).
   - A **mutation bite**, `tools/research/oracle/mutate_natives.py`, applies 6 single-native mutations to the C++:
     - `stringtoidentifier` with byte order reversed;
     - `cheatmenu` returns 1;
     - `doesfileexist` returns 1;
     - `CreateVariant` without AddRef;
     - `getcurrentlevel` + 1;
     - `playcinematic` not instant.
   - `make osi-a9` must fail on the own-models `cmp` for each mutant, and a no-op control must be MISSED.
   - A mutant that does not change the native trace on the A9 path is replaced, not counted. The anchors test checks this first, on the native trace alone.
4. **Re-entrant natives.** A native that calls `OnEvent` while a 0x82 is in flight can corrupt the outer frame: the marker sits at site+6, the nested call can error, and the depth can reach 3 or more.
   - **Pin (Task 2b → Tasks 3 and 4):**
     - `n-reenter-depth3`: a test native with `"calls": {…, "depth": 3}` calls an entry that calls it again, and the nested call is made only while the VM's nesting is below `depth`. The outer locals must be intact.
     - `n-reenter-nested-error-swallowed`: the swallowing native, with the I5 mechanism under Decision 10.
     - `n-reenter-nested-error-propagates`: the original's ordinary path, re-reported as "Script is calling %s.%s".
5. **Coverage illusion.** Taint proves safety only on the path that ran. Real values open paths the stub run never saw, and a taint bug can call a branch-relevant native safe.
   - **Pin (Task 5):** every native the flip probe marks **CHANGED** must appear UNSAFE in the taint report, with a branch, game-variable or name sink. Every **CHANGED-NULL** native must instead be tier 1 in the merged overrides (the "game-returning → must" rule of Tasks 7–9). A CHANGED native with no sink is a taint bug, and the test fails.
   - **Pin (Task 10):** the taint pass and the flip probe run on the **real-natives** run as well as on the stub run.

## Decisions (rulings by the controller; plan-review edits applied)

1. **Which acceptance rows M2a-2 owns.**

   - *Evidence:* the consult's M2a-2 row ("A8–A10"); `trace.md` §6 ("A9 (M2a-2, real natives)"); the A3 amendment.
2. **`--script` syntax.**
   - The form is `lomn_view --install DIR --script 1 [--frames N]`.
   - `Base.osi` is read through the VFS at `Root/Data/base.osi`, the literal that `GcGame::SetUpScripting` passes to `CreateVM`.
   - The parser exemptions are listed in Task 6 (I10).
   - *Evidence:* `lomn_view.cpp:7, :604`: "every option takes a value".
3. **"Generated stubs".**
   - M2a-1's runtime stub table (D11, `NativeRegistry::stub_return`, driven by the generated `ret` column) is the generated, logging stub.
   - Tiers and decided defaults go into a committed `data/osi/native_overrides.json`, one row per key: `tier`, an optional `default`, `cite`, `note`.
   - `registry.py` merges the overrides into `natives.json`, **adding no key to a row that no override names**, so an empty file is a byte-level no-op (minor m6).
   - *Evidence:* spec §6, "a decided default is one line in the registry".
4. **D13 (proposed), game objects.**
   - `CreateVariant(T*)`: null → nothing; otherwise the object's reference count goes up by 1 (0x445550: `inc dword [edi+4]` at 0x445580).
   - The handle is minted when the object first passes through `CreateVariant` (`A g` at that moment), not when it is constructed.
   - The count stored with the handle is the engine's references plus the variants' references.
   - `Dispose` → −1; at 0 → `F g`, and the host object is deleted (the original's virtual delete).
   - The same live object always maps to the same handle.
   - Each class's initial engine count is cited by Task 2a from its constructor.
   - "45 overloads" means the 45 distinct `ret_class` values over 56 game rows. Task 2a maps each class to its overload address; some classes may share one (minor m2).
5. **D14 (proposed), natives.log v2,** an amendment to `trace.md` §6; the trace format itself does not change.
   - **New records:**
     - ` G %d` after every game value (a result or a `W` write): the references the engine holds on that object after the native returns, **not counting this variant**. The heap stores total = engine + variants.
     - `C %08d <name> <a0>…<a9>`: native seq N starts an engine → script call at this point.
     - `K %6d` at the start of each frame.
     - **Reserved** (C3): `C -1 …` (a host-originated call) and `H <type>:<handle> %+d` (a reference change on the host side, outside any native). No M2a-2 code writes them unless Task 2a §6 finds a host source on the 600-frame path. Their rules are fixed now so they are not invented later.
   - **Sequence numbers** are assigned at native **entry**. Lines are written in event order.
   - **Order inside one native** (as the conformance runner already does, `lomn_osi_conform.cpp:12-14`): nested `C` calls, then `W` writes, then the return.
   - **Replay rules (I6):**
     - *Identity.* If the logged handle is live, the replay returns it with one more variant reference and writes no `A g`. Otherwise the logged handle must equal the next handle, and it is minted with `G` engine references.
     - *`C N` records.* The replay performs the nested call at that point, inside native N.
     - *`C -1` records.* The replay **never performs** one. Host-originated calls are host behaviour, implemented in both engines. The replay **asserts** that its own host's next call matches the next `C -1` record (name and arguments), the same way it asserts `cls.fn/argc`. `H` is asserted the same way.
   - **Header hash (C1).** The overrides merge changes `natives.json`, and therefore the `natives=` hash in the trace header and the digest's `T` line, but not the trace. Digest guards compare **`D` lines only**: `grep '^D' a | cmp - <(grep '^D' b)`. Headers are compared with the `natives=` field stripped: `diff <(grep '^#' a | sed 's/natives=[0-9a-f]*//') <(grep '^#' b | sed 's/natives=[0-9a-f]*//')`.
6. **What "tier 1" means inside M2a-2.**
   - Tier 1 means the script-visible behaviour is modelled: the return value, by-ref writes, nested engine calls, reference counts, and state that another native reads back (set → get).
   - Render, audio and model side effects are **not** modelled in M2a-2; M2a-3 promotes the natives it renders.
   - *Evidence:* the flip probe changes the path for 16 of 69 natives and leaves 53 unchanged.
7. **Taint sinks.** The spec's three, plus two more:
   - the 0x53 condition (spec);
   - the value 0x81 writes (spec);
   - any argument of a tier-1 native (spec);
   - the `Process` result, which the re-run rule reads (spec §3.1);
   - a 0x19 member name or a 0x83 function name that comes from a tainted string.

   The CHANGED-NULL natives are handled by the C2 rule in Review focus 5, not by a new sink.
8. **The engine → VM sources in the headless frame (C3 applied).**
   - The M2a-2 frame is the A6 frame: the key `Input` calls (KEYSPEC), then the `Process` passes with the re-run and skip rules.
   - `OnEvent(8, timerId, currentTime)` (probe 3, S7; the tuple is cited at 0x445b08–0x445b34) is included **only if Task 2a §6 finds a started timer, or another host-originated engine → script call, on the 600-frame front-end path**. The script's own timer is created with arg1 = 0 and never started (0x445906).
   - Other sources belong to later milestones:
     - `GcMouseDriver::Process` → `OnEvent(26, x, y)` every frame: M2a-3 (SDL3 input);
     - `GcLegoCamera::Process` → `OnEvent(6)`: M2a-3 (camera spline);
     - character, Toa and collision processes: M3, unless Task 2a's asm shows that one runs on the front-end within 600 frames. In that case Task 2a stops and reports.
9. **The saver, the INI, `doesfileexist` and the mods in M2a-2 (I1, I2, m9 applied).**
   - **Saver getters** return the default save state. It is cited from `GcSaver::InitData` 0x5d4700, `ResetData` 0x5d5490, `LoadIni` 0x5d4890, and the **static `.data`** bytes they set: `setmask` → byte 0x7474a4; `sethealth`/`setenergy` → 0x7474a0/0x7474a8. It is not cited from a constructor; the corpus has no `GcSaver` constructor.
   - **`gcsaver.cheatmenu` is an INI query.** `GcSaver::CheatMenu` 0x5d4fc0 calls `GetPrivateProfileStringA` with section `"Misc"`, key `"CheatMenu"` and default `""`, then compares the result with `"LEGOTester"`: equal → 1, else 0. The owner's `Bionicle.ini` has `[Misc]` but no `CheatMenu` key, so the decided default is **int 0**, with `note: "ini → M2a-3"`. The same shape applies to `GcSaver::Cheat` 0x5d4d00, `BadCheat` 0x5d4e40 and `CheatDebug` 0x5d4f00 if the path reaches them.
   - **`doesfileexist` is a block-file lookup** (`SrBlockFileExists` 0x54ddc0). It never checks loose files while `Main.blk` is loaded.
   - **`bettersaver.*`** follow the DLL bodies (Task 2a §9 pin). The owner's install has no `User/` directory, so the map is empty and `getbooleanvalue` returns int 0.
10. **The swallowed nested error (carried, Important; I5 applied).**
    - Task 2a decodes the `.exc` records of every function on the 35 statically re-entrant chains, between the native body and 0x60b320, with `tools/osi/exc.py`.
    - **(a)** If none catches (expected: opcodes.md "After an error" finds catches only in `SetUpScripting` and `_WinMain`), swallowing is **unreachable in the original**, and the port defines one mechanism for both engines:
      - The non-outer catch in `Vm::call` sets `nested_error_pending_ = true` (oracle: `_nested_error`), stores the inner message, and rethrows. The inner error gets **no** `E` line of its own.
      - `invoke_native` (oracle: the 0x82/0x83/0x84 handlers) checks the flag **after the native returns, before the by-ref pops and the result push**. If set, it raises `VmError("Undefined: native returned after a nested engine-call error: <inner message>")` at the outer instruction.
      - `expect_error.depth`/`top` describe the stack as the native left it: the inner marker and the partial frame are still there.
      - The outer `record_error` / `reset_after_error` clear the flag. Under D10 the reset pops to the *outer* marker, so the state is clean afterwards.
    - **(b)** If a catch exists, the asm defines the state, both engines model it, and the plan is re-checked.
    - **Declarative test-native fields:**
      - `"swallow": true`: the runner catches the nested call's `VmError` inside the native, and the native returns its `returns` normally.
      - `"calls": {…, "depth": d}`: the nested call is made only while the VM's nesting is below d.
    - *Evidence:* the C++ resumes at the failing instruction (`engine/src/osi/vm.cpp:92-116`), the oracle at the next one (`tools/research/osi_vm.py:1003-1030`).
11. **D15 (proposed), the nesting cap after re-measurement.**
    - Keep 64 while 64 ≥ 4 × the measured maximum M; otherwise use 4 × M.
    - `STACK_SIZE` ≥ 4.5 × cap × the bytes per level, measured on a **real** re-entrant chain. 4.5× is the M2a-1 margin.
