# M2a-2 — Native framework, `Setup` to the first `Process`, `lomn_view --script`: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Base.osi` runs `Setup` and N `Process` frames headless with **real** natives wherever a native's result can change what the script does, natively and as wasm32, behind `lomn_view --script 1`. Every native the run reaches is tier 1 (implemented, cited) or tier 2 (a stub that a taint pass proves harmless). An independent Python model of every tier-1 native agrees with the C++ byte-for-byte on the trace.

**Architecture:** M2a-1's VM is unchanged except for small additions. Around it goes a native framework:
- a game-object model that mirrors `CreateVariant(T*)` and the engine's reference counts (handles, never pointers, D7);
- a `HostContext` that owns per-subsystem state (area director, saver, timers, ...);
- a `ScriptHost` that owns the `ScProcessManager` frame loop, now shared by `lomn_osi_run` and `lomn_view`;
- natives bound by group, each citing its wrapper body and the method it calls.

The Python oracle gets its own framework and its own native models, written by different agents from the same citations, plus the A10 taint pass. The tier and decided-default data live in one committed overrides file that `tools/osi/registry.py` merges, so `data/osi/natives.json` stays generated.

**Tech stack:** C++17 (CMake, doctest), emscripten wasm32 under node 20, Python 3 (stdlib only for the oracle), GNU make. Read as data only: `objdump --x86-asm-syntax=intel` on the exe and on the Beta 1.5.0 mod DLLs; the Ghidra corpus `gen/decomp`.

**Spec:** `docs/superpowers/specs/2026-10-08-lomn-web-m2-design.md`, §3 (what the original does), §6 (tiers), §7 (M2a-2 row; A3 amendment, A8, A9, A10, and A15 rows for the new run) and rulings D1–D12 with D8′.

**Contracts this plan extends:** `docs/osi/opcodes.md` ("Engine calls", "After an error"), `docs/osi/trace.md` §6 (natives.log), `docs/osi/conformance.md` §1 and §6, `docs/osi/types.md`.

**Precedent:** the M2a-1 plan (`2026-10-08-lomn-web-m2a1.md`) and its ledger (`.superpowers/sdd/2026-10-08-lomn-web-m2a1/progress.md`).

## Review focus (failure modes that no task's own tests cover, and the test that now pins each)

1. **A shared misreading of a native.** C++ and Python read the same decomp line the same wrong way: a hash multiplier, an initial reference count, a field offset, a default value. Agreement then proves only consistency.
   - **Pin (Tasks 7–9, each side):** one `asm-pin` test per implemented native. Its expected value is computed by hand from `objdump` bytes and cites the instruction address. Each side writes its own.
   - The Opus reviewer of each pair re-derives 3 pins at random from the asm without reading either implementation, and states any pin that both sides took from the decomp alone.
2. **Engine reference counts and `F g` timing.** A game object the engine still holds is freed when the script drops its last variant, or one the engine releases is never freed. This shows only as a trace difference many frames later, or never on the A9 path.
   - **Pin (Task 2 → Tasks 3 and 4):** three conformance programs that use the new declarative field `{"game": "<Class>", "engine_refs": k}`:
     - `n-game-engine-ref-survives`: k = 1, two `Dup`s, three `Pop`s → no `F g`, `heap.live.g` = 1;
     - `n-game-engine-ref-zero`: k = 0 → one `F g` at the last `Pop`;
     - `n-game-identity`: the same object returned twice → one `A g`, and 0x60 gives 1.
   - Both runners must pass them.
3. **The replay hides a native divergence.** The A9 replay leg compares only VM semantics, so a C++ native that is wrong in the same way as the replayed log would pass.
   - **Pin (Task 10):** the A9 run also compares the C++ digest against Python running **its own models** (`--real-natives`).
   - A **mutation bite** step, `tools/research/oracle/mutate_natives.py`, applies 6 single-native mutations to the C++ and requires `make osi-a9` to fail on the own-models `cmp` for each:
     - `stringtoidentifier` +1;
     - `cheatmenu` result inverted;
     - `doesfileexist` case-sensitive;
     - `CreateVariant` without AddRef;
     - `getmp3player` returning a fresh handle per call;
     - `playcinematic` not instant.
   - A no-op control must be MISSED.
4. **Re-entrant natives.** A native that calls `OnEvent` while a 0x82 is in flight can corrupt the outer frame. Risk points: the marker is site+6, the nested call can error, and the depth can reach ≥ 3.
   - **Pin (Task 2 → Tasks 3 and 4):**
     - `n-reenter-depth3`: a test native calls an entry that calls it again, 3 levels deep, and the outer locals are intact;
     - `n-reenter-nested-error-swallowed`: the swallowing native of the carried item, with the ruling's expectation;
     - `n-reenter-nested-error-propagates`: the original's ordinary path, re-reported as "Script is calling %s.%s".
5. **Coverage illusion.** Taint proves safety only on the path that ran. Real values open paths the stub run never saw, and a taint bug can call a branch-relevant native safe.
   - **Pin (Task 5):** every native that the flip probe marks CHANGED must appear in the taint report with a branch or game-variable sink. A CHANGED native with no sink is a taint bug, and the test fails.
   - **Pin (Task 10):** both the taint pass and the flip probe run on the **real-natives** run as well as on the stub run.

   - *Evidence:* `lomn_view.cpp` lines 7 and 604: "every option takes a value" (`--survey 1`, `--manifest 1`); the spec's `--script --frames 1` would break that parser rule.
3. **"Generated stubs".**
   - *Recommend:* M2a-1's runtime stub table (D11, `NativeRegistry::stub_return`, driven by the generated `ret` column) is the generated, logging stub. `natives.log` already logs every call with its arguments and return. No C++ code is generated.

   - *Evidence:* spec §6, "A decided default is one line in the registry"; generating 1,049 C++ functions would change no behaviour.
4. **Game objects (D13, proposed).**
   - `CreateVariant(T*)` semantics: null → nothing; otherwise the object's reference count +1.
   - The handle is minted when an object first passes through `CreateVariant` (`A g` then), not when it is constructed. Engine-internal objects therefore never consume handles, and handle order depends only on what the script sees.
   - The count lives with the handle: references held by the engine plus references held by variants. `Dispose` −1; at 0 → `F g` and the host object is deleted (the original's virtual delete).
   - The same live object always maps to the same handle (identity, 0x60).
   - *Evidence:* the 0x445550 read above; opcodes.md "Pop and ownership" ("types 1, 5 and 0x20..0xfe release a reference (count at +4, virtual delete at zero)").
   - Each class's initial count comes from its constructor and is cited by Task 2 per class on the path.
5. **natives.log v2 (D14, proposed),** so the replay can reproduce engine references and re-entrant calls. Additions to `trace.md` §6 (the trace format itself is unchanged):
   - ` G %d` after every game value (result or `W`): the references the engine holds on that object after the native returns, not counting this variant.
   - `C %08d <name> <a0>…<a9>`, written when native seq N starts an engine → script call (`-1` = the host's own call, e.g. a timer). The replay performs it at that point.
   - `H <type>:<handle> %+d`: a host-side reference change outside any native.
   - `K %6d` at each frame start.
   - The sequence number is assigned at native **entry**; lines are written in event order.
   - *Evidence:* M2a-1's log has no way to express engine references or nested calls; A9 needs both (spec §5.4: the replay makes any disagreement VM semantics).
6. **What "tier 1" means inside M2a-2.**
   - *Recommend:* tier 1 = the script-visible behaviour is modelled: return value, by-ref writes, nested engine calls, reference counts, and state that another native reads back (set → get).
   - Render, audio and model side effects (`setzdepth`, `sethudposition`, `setcolor`, sounds) are **not** modelled in M2a-2. Their return is nothing, so the taint pass makes them tier 2. M2a-3 promotes the ones it renders.
   - *Evidence:* the flip probe: 16 of 69 natives change the path; 53 do not.
7. **Taint sinks.**
   - *Recommend:* the spec's three sinks plus two:
     - the 0x53 condition;
     - the value written by 0x81 (SetGameVariable);
     - any argument of a native whose tier is 1;
     - the `Process` result, which the re-run rule reads (spec §3.1);
     - the value of a 0x82/0x83 call whose result decides a script→script call target: a 0x19 member name by string, or a 0x83 function name.
   - *Evidence:* opcodes.md 0x19/0x83, where a tainted string picks the code that runs.
8. **Engine → VM sources in the headless frame.**
   - *Recommend:* the M2a-2 frame is the A6 frame plus `GcTimer` triggers:
     - the key `Input` calls (KEYSPEC);
     - the `Process` passes with the re-run and skip rules;
     - `OnEvent(8, timerId, currentTime)` (probe 3, S7).
   - `GcMouseDriver::Process` → `OnEvent(26, x, y)` every frame belongs to M2a-3 (SDL3 input), and so do `GcLegoCamera::Process` → `OnEvent(6)` and the camera spline.

    - *Recommend:* Task 2 decodes the `.exc` records of every function on the 35 statically re-entrant natives' chains between the native body and 0x60b320.
      - **(a)** If none catches (expected: opcodes.md "After an error" found catches only in `SetUpScripting` and `_WinMain`), swallowing is **unreachable in the original**.
