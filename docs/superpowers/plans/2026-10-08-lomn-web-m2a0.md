# M2a-0 — Corpus completion and citation tables: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** complete the decompiled corpus so that every one of the game's 1,056 script-native registrations, and its body, is a decompiled function. Then generate the three citation tables M2a-1 builds from: opcodes, natives and variant types.

**Architecture:**
- A data-only Python step computes seed addresses from the exe.
- A new Ghidra pre-script creates functions at those addresses, and a post-script fixes `CreateVariant`'s hidden return pointer (A11).
- `make decomp` re-runs into the M2 worktree's own `gen/` and Ghidra cache.
- Python generators read the corpus and the exe and emit `docs/osi/opcodes.md`, `docs/osi/types.md` and `gen/osi/natives.json`.

**Tech stack:** Python 3 (the repo `.venv`, pytest), Ghidra 12.1.4 headless + JDK 21 (Java GhidraScripts as in `tools/decomp/ghidra/`), GNU make.

**Spec:** `docs/superpowers/specs/2026-10-08-lomn-web-m2-design.md` (§2, §6, §7 M2a-0, A1–A4). Probe evidence: `docs/knowledge/research/2026-10-08-m2a0-probe1-seeding.md`, `…-probe2-fonts.md`, `…-probe3-input.md`, and the consult `2026-10-08-m2-osi-vm-consult.md`.

## Global constraints

- Never run the game's `.exe` or `.dll`. Parse them as data only.
- Never commit game data, renders of game data, or decompiled code blocks. Names, addresses, counts and short formulas are fine. `gen/` stays out of git.
- No foreground command over ~2 minutes. `make decomp` and full test runs go in the background with a wait that exits on success, on failure and on a deadline.
- zsh: quote globs and words that start with `=`. Never execute an unquoted `$VAR` of arguments.
- Before writing more than 200 MB, check `df -h /` and stop if under 2 GB is free.
- This worktree's `.env.local` sets its own `LOMN_DATA` and `LOMN_CACHE` (`~/Library/Caches/lomn-web-m2`). Never point `LOMN_CACHE` at the shared M1 cache (`~/Library/Caches/lomn-web`).
- Every number a test pins must be one you measured in this task, and the commit message names the command that produced it.
- Never push, amend, rebase or stash. Never dispatch subagents. Never `rm` or run `npm` through a `node_modules` symlink. Commit only the files your task names.
- If blocked, write a partial report and stop.

## Review focus

1. **The exe is not the canonical build.** `run_decomp.run` already refuses it by sha. The seed step must refuse too, by the same check (`lomn_data.BUILDS["canonical"]["exe_sha256"]`), before it parses anything.
2. **The cache is reused after the seed list changes.** The seed file and every new script must be part of `analysis_key()`. A test changes a seed byte and asserts that the key changes.
3. **The first registration in an initializer has 8–13 `push imm32` candidates** (`ScInitFunc` pushes come first). The extractor takes the *last* `.text` push before the call; the probe measured this as matching the decomp on 1,054/1,054. A test pins one first-site case.
4. **Duplicate registrations** (7 `GcHudSprite` names, two bodies each). The registry must record both and mark the winner, citing the map-insert behaviour read from `0x5fab30`. It must not silently keep the last one.
5. **Type ids are assigned lazily, in static-init order.** `types.md` must state the order rule and list every type id the registry uses. It must not invent numeric ids that the binary assigns only at run time.

### Task 1: Seed addresses from the exe (data only)

**Files:**
- Create: `tools/decomp/seed_addrs.py`
- Create: `tools/tests/test_seed_addrs.py`

**Interfaces:**
- Produces `seed_addrs.compute(exe_bytes: bytes) -> dict` with these keys:
  - `crt`: list of int, every dword of the `.CRT` section that points into `.text`, in file order;
  - `reg_sites`: list of `{"site": int, "fnptr": int, "candidates": int}`, one per `E8 rel32` call to `0x5fab30` (RegisterFunction), in ascending site order;
  - `type_sites`: list of int, `E8` calls to `0x5fae00` (RegisterType);
  - `seeds`: the sorted, de-duplicated union of `crt` and every `fnptr`.
- CLI: `python tools/decomp/seed_addrs.py <exe> <out_dir>`. It refuses a non-canonical exe and writes `<out_dir>/seed_addrs.txt` (one `0x%08x` per line, sorted) and `<out_dir>/reg_sites.json`.

Assert `crt`, the two `fnptr` values (the last `.text` push before each call), the `candidates` counts, and `seeds`.
  - **Real exe** (use the `lomn_data` fixture pattern of `test_lomn_data.py`; skipped only when the data is absent, as other data tests are):

    - the `fnptr` values are 1,056 distinct values;
    - the 79 fnptrs already present in `gen/decomp/functions.jsonl` (the pre-re-run corpus) are a subset of `seeds`. Measure that count here and pin it.

- [ ] **Step 2:** run `.venv/bin/python -m pytest tools/tests/test_seed_addrs.py -q`. Expected: FAIL (module missing).
- [ ] **Step 3: Implement.**
  - Parse the PE headers as `scan.py` in the probe did: section table, image base, VA ↔ file offset.
  - `.CRT` is the section named `.CRT`; read every aligned dword in it.
  - For `E8` sites, scan every byte of `.text` for `0xE8` and keep those whose `rel32` target equals the function address.
  - For each site, walk back from the site to the previous registration site (or the start of the enclosing `.CRT` initializer), collect every `0x68 imm32` whose imm lies in `.text`, take the last one, and record the count.
