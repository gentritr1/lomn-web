# LOMN Web M1a-4 (Hardening) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close M1a's hardening row with three things:
- a fuzz corpus over every real file format (A11);
- performance entries per area (A12);
- the texture-cache flag, default off.

Also fold in the test-strength items the M1a-3 final review deferred.

**Architecture:** no new subsystems.
- **Fuzzing:** a single sanitizer-built fuzz driver that mutates real files read-only, with a fast synthetic-seed subset in ctest.
- **Performance:** an adapter from `lomn_view` metrics to `perf/history.jsonl`.
- **Texture cache:** a cache in the area loader, keyed by texture path and checked by content hash, behind the flag.
- **Oracle extensions:** XFORM and LIGHT in A9, plus `pack_uniforms` in the FFP oracle.

## Global Constraints
- **All M0–M1a-3 constraints hold.** In particular:
  - Never commit game data, renders or anything derived from game files (fuzz crash inputs derived from real files stay under `build/`).
  - Never run the game's `.exe`/`.dll`.
  - Untrusted input: caps come from measured maxima, and a rejection leaves no partial state.
  - Native and wasm32 logs must stay identical.
  - rhi stays additive only.
- **Long work runs detached.** No tool call blocks more than about 2 minutes in the foreground. Builds, `make check`, fuzzing and perf runs go in the background with a timeout and a failure-aware completion check.
- **No thresholds without measurement** (A12): record the measurement first; a regression guard uses only measured noise (`perf_history.py` rule).
- **The A7, A9 and A9-f2 goldens are regenerated only when a task says so,** with every changed line explained in the commit body.
- **Real renders must stay byte-identical:** lev1/vllg, lev2/ghut and lev4/crss at the default camera, compared with the M1a-3 renders (the controller supplies the paths). `make a9-sweep` must stay 123/123.

## Review Focus
1. **Fuzzing that never reaches the deep code.** A mutation that only hits the header check proves little. Pinned by per-format accepted/deep counts printed by the driver, and a minimum deep-reach fraction asserted in the ctest subset (T1).
2. **Perf numbers quoted without reconciling the sample count.** Pinned by a check that frames rendered equals frames expected, and that dt samples equal frames − 1, before any p50/p95 is recorded (T2).
3. **A texture cache that changes pixels or leaks across areas.**
   - Pinned by flag OFF giving byte-identical logs and renders to today.
   - Pinned by flag ON giving byte-identical renders.
   - The cache key includes the content hash, so the same path with different bytes is a miss (T3).
4. **Oracle extensions that mirror the implementation instead of re-deriving it.** Pinned by deriving XFORM and LIGHT from the oracle's own parsers, and by a mutation of the shim's world matrix and light packing that only the extended oracle catches (T4).

### Task 1: A11 fuzz corpus over all real formats

**Files:**
- Create: `engine/tests/fuzz_formats.cpp` (driver), `tools/research/fuzz_formats.md` (how to run, read by the Makefile help).
- Modify: `engine/CMakeLists.txt` (fuzz driver target; ctest `fuzz_formats_smoke`, native and wasm32), `Makefile` (opt-in `fuzz-formats`, not part of `make check`).

**Behaviour:**
- **Formats covered:**
  - BLK tables and entries (incl. LZSS);
  - SLB tables (OBJ/POS/LIGHT/textures.slb);
  - binary `.x`;
  - DDS;
  - TGA;
  - OSI.
- **Mutation kinds:** truncation at random prefixes, bit flips, length-field inflation (u32/u16 fields set to size±k, 0, 0xffffffff), chunk duplication and deletion.
- **Seeds:** real files read only from `$LOMN_DATA` (sampled per format, deterministic RNG seed), plus each format's synthetic unit-test inputs.
- **Invariants checked on every input:**
  - no sanitizer report;
  - an accepted parse satisfies the format invariants (sizes consistent, indices in range, Image rgba == w·h·4);
  - a rejected parse leaves the output default and has a non-empty error string;
  - per-input wall time is under 2 s;
  - per-input RSS growth is under 64 MB natively;
  - wasm32 heap growth is under 256 MB.
- **Output:** per format: inputs, accepted, deep-reach count (an input that got past the header into the body loop — instrument a counter), findings.
- **ctest `fuzz_formats_smoke`:**
  - synthetic seeds only, 20,000 inputs per format, ≤ 20 s;
  - asserts 0 findings, and that deep reach is at least 5 % of inputs per format.

**Acceptance (the controller re-runs):**
- `make test-native && make test-wasm` green, including the smoke test.
- `make fuzz-formats FUZZ_N=200000` with `LOMN_DATA` set, under `build/asan` (ASan+UBSan, `-fno-sanitize-recover`), both natively and as wasm32 (Node, 2 GB cap), prints per-format totals with 0 findings.
- Paste the totals.

**Proof the fuzzer bites:**
- Reintroduce, in a scratch copy, one known past defect per format family:
  - the M1a-1 BLK name-run quadratic (remove the cap);
  - the M1a-3 textures.slb record copy (remove the cap);
  - an out-of-bounds read (remove one TGA RLE bound).
- The fuzzer must report each within its normal run. Paste the evidence.

- [ ] Step 1: Write the smoke test (it fails because the driver is missing). Run `make native` and paste the error.
- [ ] Step 2: Implement the driver and the Makefile target. Run `make test-native && make test-wasm`, detached.
- [ ] Step 3: Real-data runs (native ASan and wasm32), plus the three reintroduced-defect runs in scratch copies.
- [ ] Step 4: Append the totals to `docs/knowledge/measurements.md`.
- [ ] Step 5: Commit, with subject `M1a-4: A11 fuzz corpus over BLK/SLB/.x/DDS/TGA/OSI (real seeds, native+wasm32, deep-reach asserted)`.

### Task 2: A12 perf entries per area

**Files:**
- Modify: `tools/harness/perf_history.py` (scene `area:<lev>/<area>`; extra recorded fields without thresholds), `Makefile` (`perf-areas`), `engine/tools/lomn_view.cpp` (only if a metric is missing).

**Behaviour:**
- `make perf-areas` (needs `LOMN_DATA`) runs `lomn_view` on lev1/vllg, lev2/ghut and lev4/crss: real GPU, 600 frames, 3 reps each, warm.
- It records one history row per run with:
  - commit and machine;
  - scene `area:lev1/vllg`;
  - load, decode and upload ms;
  - frame_ms p50 and p95;
  - frames and expected_frames;
  - draws, pipelines, texture_bytes;
  - loadavg at start and end.
- **Reconciliation check before recording:** frames == expected_frames, and dt samples == frames − 1. If it fails, nothing is recorded and the exit is non-zero.
- `check` guards only frame_ms_p50 with the existing noise rule. The other fields are recorded, not guarded.
- Seed 5 accepted baselines per area. Note the loadavg; if loadavg > 6, record the baseline as provisional in the row (`"provisional": true`). The guard uses only non-provisional rows.

**Acceptance:**
- Unit tests in `tools/tests/test_harness.py`:
  - a row with frames ≠ expected_frames is rejected;
  - provisional rows are ignored by the guard;
  - a regression larger than noise fails;
  - a change within noise passes.
- `make perf-areas` prints PERF OK for each area, or reports provisional baselines.
- `make check` unchanged.

- [ ] Steps: tests first (RED), implement, run, commit with subject `M1a-4: A12 per-area perf history (reconciled samples, measured-noise guard, provisional baselines under load)`.

### Task 3: Texture cache across area loads (flag, default off)

**Files:**
- Modify: `engine/include/lomn/view/area.h`, `engine/src/view/area.cpp` (`AreaOptions::texture_cache`, or a `TextureCache` object passed in), `engine/tools/lomn_view.cpp` (`--texture-cache on|off`, plus the survey using it when on), and tests.

**Behaviour:**
- **The cache:** a process-lifetime CPU-side cache of decoded RGBA8 plus its mip chain.
  - Keyed by (canonical texture path, sha-like content hash of the entry bytes).
  - Capped by bytes: 256 MiB by default, LRU eviction.
  - It never hands out pointers into evicted data.
- **Default OFF:** with the flag off, behaviour, logs and renders are byte-identical to today.
- **Flag ON:**
  - the survey (`--survey 1 --texture-cache on`) reuses decodes across areas;
  - metrics report `texture_cache: {hits, misses, bytes, evictions}`;
  - renders are byte-identical to flag OFF.

**Acceptance:**
- Unit tests: same path with different bytes misses; eviction under a small injected cap; flag OFF never touches the cache.
- Controller check:
  - the three renders with ON and with OFF are byte-identical to each other and to M1a-3;
  - the survey ON vs OFF has identical per-area fields apart from timing and the cache block;
  - report the measured decode-time saving (3 reps each way, ABAB order, loadavg recorded; no claim of a win smaller than the measured spread).

- [ ] Steps: tests first, implement, measure, commit with subject `M1a-4: texture decode cache across area loads (flag, default off; content-hash keyed; measured)`.

### Task 4: Deferred test-strength items from the M1a-3 final review

**Files:**
- `tools/research/oracle/a9_oracle.py`
- `tools/research/oracle/ffp_oracle.py`
- `engine/tests/test_gpu_ffp.cpp`
- `engine/src/d3d/device8.cpp`
- `engine/src/view/area.cpp`
- tests

**Items:**
- (a) Non-finite POS start positions and non-finite `.x` vertex positions:
  - a POS record with a non-finite pos is skipped with a warning, and the camera falls back as for no POS;
  - a mesh with any non-finite position is rejected at load with a warning (the model is skipped).

  Tests for both.
- (b) `a9_oracle.py` also emits and compares XFORM checksums (world/view/projection/texture matrices) and LIGHT lines, derived from its own parsers and math.
  - The A9 filter is then narrowed accordingly.
  - Prove it bites: a scratch-copy mutation of the shim's world matrix (e.g. a transposed RotX) and of light packing (swapped diffuse/ambient) must each fail `a9_oracle_synthetic`. Before this task, both are caught only by gpu_ffp.
  - `make a9-sweep` stays 123/123.
- (c) `ffp_oracle.py` also checks `pack_uniforms` byte layout for its sampled cases: fog distances and mode, ALPHAREF, TFACTOR, matrices.
- (d) `test_gpu_ffp.cpp` computes its blend expectation from `pipeline_key(s).blend`, not `rs[ALPHABLENDENABLE]`. Add one ONE/ZERO case.
- (e) `device8.cpp` writes the D3D8 default light only when enabling a never-set light, not on disable. The state log is unchanged on real data (verify with the sweep).

**Acceptance:**
- `make check` green;
- `make a9-sweep` 123/123;
- the A9 goldens regenerated only if (b) changes the filtered lines, with an explanation;
- renders byte-identical.

- [ ] Steps: one commit per item (a)–(e), each test-first.
