# LOMN Web M1a-1 (Data path) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read the original game's data exactly the way the original engine does, with no GPU involved:
- BLK blockfiles (+LZSS) and the area → level → Art lookup chain (both search orders);
- SLB tables with pointer fix-ups, and OBJ/POS/LIGHT placement with the decompiled routing;
- binary `.x` meshes (vertex colours, last mesh wins, D3DX-style vertex split, attribute table);
- DDS/TGA textures decoded to RGBA8.

Everything is validated against independent oracles over the real install.

**Architecture:**
- New library `lomn_sage` (namespace `lomn::sage`) on top of M0's `lomn_core`. Each header names the original function and address it reproduces.
- Two additive methods on M0's `lomn::fs::FileSystem` (`size`, `read_range`; spec M1 R9) enable on-demand entry reads.
- A native CLI, `lomn_datacheck`, emits whole-data JSON. A Python oracle compares it against independent readers.

**Tech Stack:** as M0 (C++17, CMake + Ninja, doctest, emsdk 6.0.11 for wasm32 tests under Node, Python 3.14).

**Spec:** `docs/superpowers/specs/2026-10-07-lomn-web-m1-design.md` (§2.1, §2.2, §3 row M1a-1, §4 A1–A6, §5 security, §7 R1–R10). Parent: `2026-10-07-lomn-web-port-design.md`.

**Reference bundle:** `docs/superpowers/plans/2026-10-07-m1a1-ref/` (REF1).
- Built 2026-10-07 and independently re-verified by the controller: native ctest 3/3; oracle 39/39 in 21 s.
- `REPORT.md` holds every measured number.
- *"Create X with the content of REF1/X"* = copy byte for byte. M0-owned files are changed only via `REF1/fs_api.patch` (checked to apply cleanly to the current tree; it reproduces REF1's `fs.h` and `memory_fs.cpp` exactly, while `disk_fs.cpp`/`test_fs.cpp` also carry M0's later fix round).

## Global Constraints

- All M0 global constraints still hold. In particular:
  - Never commit game data or exe-derived output (`gen/`); never run the game's `.exe`/`.dll`.
  - `$LOMN_DATA`-gated tests skip with `SKIPPED (no LOMN_DATA)`.
  - Timeouts on every external command; no fixed sleeps.
  - Implementers commit only their task's files with the `-m subject -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"` form.
- **All parsing treats game files as untrusted** (spec §5):
  - u64 or `count ≤ remaining/stride` size arithmetic;
  - every offset and length bounds-checked;
  - `.x` nesting ≤ 64;
  - LZSS output capped at the declared size, with a ratio cap;
  - DDS dimensions ≤ 4096; cube and volume textures rejected.
- **Faithful, not "fixed".** Reproduce the decompiled behaviour, including:
  - the 40-byte unterminated-name miss (R4);
  - the decompiled routing order (R1);
  - Load (area → level → Art) vs Exists (Art first) orders.
- **wasm32 is a first-class target.** Every sage unit test passes natively AND as wasm32 under Node.
- **Oracles stay independent.** The C++ output is compared with `tools/research/*.py` and `tools/research/oracle/*.py`, never with itself.

## Review Focus

1. **Truncated or hostile game files** (a blockfile cut short, an SLB relocation pointing outside the buffer, a `.x` nested 100,000 deep, an LZSS stream that claims 4 GB) must produce an error, never a crash or hang. Pinned by the malformed-input cases in `test_sage_*.cpp` (Tasks 2–6) and the ASan/UBSan run (Task 7).
2. **Case and path quirks:**
   - The game asks for `Root/Data/Levels/...` with mixed case while the disk has lower case.
   - Lookups ignore the directory part.
   - Pinned by `test_sage_blockchain.cpp` and the A2 oracle (Task 7).
3. **Load vs Exists order divergence** for names present in both Art and an area blockfile. Pinned by `test_sage_blockchain.cpp` (Task 3).
4. **A model drawn that the original wouldn't draw** (vllg's `main1`/`tre1`/`rock`/`drll`). Pinned by A6 in the oracle (Task 7).
5. **The FS API addition breaking M0 behaviour.** `test_fs.cpp` keeps all M0 cases and adds range-read cases. `make test-wasm` must still show native == wasm32 traces (Task 1).

### Task 4: SLB tables and placement routing

**Files:**
- Create from REF1: `engine/include/lomn/sage/slb.h`, `engine/src/sage/slb.cpp`, `engine/tests/test_sage_slb.cpp`
- Modify: `engine/CMakeLists.txt`

**Interfaces:**
- Produces:
  - `lomn::sage::Slb` (bounded GetSLKFile fix-ups)
  - views `ObjRecord` (60 B), `PosRecord` (20 B), `LightRecord` (44 B)
  - `route(flags)`, in the decompiled order (spec §2.1)
  - `is_cinematic_obj(name)`
- SLB fix-up layout (spec §2.1 item 4; REF1 `slb.h`/`slb.cpp`):
  - trailer at `m = (len - 4) & ~3` must hold `0x00C0FFEE`;
  - relocation `count` at `m - 4`; slot k at `m - 4 - 4k`;
  - the pointer **field** offset is the slot value `& ~3`; the pointer **target** is used unmasked (OBJ records start at 0x16).

- [ ] **Steps 1–5** follow the Task 3 pattern:
  - test first: `test_sage_slb.cpp` (8 cases); expect a build error;
  - then `slb.h`/`slb.cpp` + the CMake source;
  - `make test-native && make test-wasm` at 100%;
  - commit with subject `M1a-1: SLB fix-up reader, OBJ/POS/LIGHT views, decompiled routing`.

  The routing test must include flags `0x18`, `0x28` and `0x118`: Beta data never exercises them, so they pin the decompiled order.
