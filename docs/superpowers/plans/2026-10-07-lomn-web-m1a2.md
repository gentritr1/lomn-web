# LOMN Web M1a-2 (First pixels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw a game area unlit and textured on the engine's own render interface, then write it to a PNG with `lomn_view`.

**Architecture:**
- Additive `rhi` calls: vertex/index buffers, mipmapped RGBA8 textures, samplers, depth targets, bind groups and indexed draws. Both backends share one validation registry.
- A new library, `lomn_area`, adds:
  - D3D-convention math;
  - CPU box-filter mips;
  - the area loader (BlockChain → OBJ routing → `.x` → textures);
  - an unlit renderer;
  - a synthetic scene for the A7 contract.
- `lomn_view` drives it, from the CLI or headless.

**Tech Stack:** the same as M0/M1a-1.

**Spec:** `docs/superpowers/specs/2026-10-07-lomn-web-m1-design.md`, specifically:
- §2.1–§2.3;
- §3 row M1a-2;
- §4 A7 and A8 (preliminary);
- §5;
- §7 and §7.1 R11–R16.

Parent spec: `2026-10-07-lomn-web-port-design.md`. Its rule "rhi frozen in M0; additive changes only, reviewed" binds this plan.

## Global Constraints

- **M0 and M1a-1 constraints still hold:**
  - never commit game data, renders of game data, or exe-derived output;
  - never run the game's `.exe`/`.dll`;
  - every external command has a timeout, and there are no fixed sleeps;
  - commit only the task's files, with `-m subject -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"`.
- **`rhi` stays additive.** Every M0 call keeps its behaviour, and valid M0 calls log byte-identical null-backend text. Proven by: `determinism_null`, `gpu_triangle`, the browser smoke and `test_rhi_null` all unchanged.
- **Untrusted input:** every loop over file-provided counts is bounded. The per-area caps (spec R16) are 1,024 placements, 4,096 draws, 1,024 textures, 256 MiB of texture bytes and 64 MiB of geometry. Rejected areas leave no partial state.
- **Determinism:** null call logs are identical across runs and between native and wasm32 (no pointers, no unordered iteration, no timings in logs).
- **GPU pixels are not bit-stable at alpha-tested edges.** One render in at least 17 of the same view differed in 2 pixels (REF2 report). Real-area PNG comparisons therefore allow ≤ 16 differing pixels at ≤ 8 levels per channel. Null logs and the synthetic A7 probes (±2) stay exact.
- **`engine/tests/data/a7_calls.txt` is a regenerated artefact, not a frozen contract.**
  - The invariants are: native == wasm32, run A == run B, and 10 draws.
  - Regenerate it only with `build/native/lomn_view --synthetic 1 --backend null --out engine/tests/data/a7_calls.txt`.
  - Only in a commit whose message explains every changed line.

## Review Focus

1. **M0 regression through the rewritten WebGPU backend (855 lines, now registry-based).** An M0 pipeline drawn into a depth target, or a mesh pipeline passed to M0 `draw()`, must not change M0 pixels and must not reach Dawn unvalidated. Pinned by `test_gpu_mesh.cpp` (Task 2) plus the unchanged M0 GPU, determinism and smoke tests.
2. **Hostile areas.** An oversize count, a missing model or texture, or a mismatched bind group must reject cleanly, render with 0 rejected calls when accepted, and leave no partial state. Pinned by the 1,500-case deterministic fuzz and the cap boundary cases in `test_view_area.cpp` (Task 3).
3. **D3D convention errors** (row-vector upload, `RotX` sign and order, RH depth range). They are invisible in counts and visible only in pixels. Pinned by:
   - the math cases in `test_view_area.cpp` (Task 3);
   - the A7 Dawn pixel probes (Task 4);
   - the mutation scripts (Task 5).
4. **Alpha correctness:**
   - a framebuffer alpha leak (the bug REF2 found);
   - alpha-test threshold off-by-one (GREATER vs GREATEREQUAL);
   - DXT5 drawn opaque.

   Pinned by the blend probe in `test_gpu_mesh.cpp` (Task 2), `mutate2.py` (Task 5) and the A7 probes (Task 4).
5. **Native ≠ wasm32 drift in the area renderer.** Pinned by the A7 null log `cmp` in `make test-wasm` (Task 4).
