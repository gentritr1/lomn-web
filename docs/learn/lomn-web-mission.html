The Mission

What we are building, why, and how far we are. Read this page first.

The game

There is an old LEGO computer game from 2001. It was never finished or sold. Fans saved a copy. But it only runs on old Windows computers. We want it to run in any web browser.

BIONICLE: The Legend of Mata Nui (LOMN) is a PC game. Saffire made it for LEGO in 2001. LEGO cancelled it before release.

A fan group named TheLegendOfMataNui keeps a playable beta build. We use their release 1.5.0. It includes two community mods: BetterSaver and a mod loader (ijl15.dll).

The game is a Windows 32-bit program. It uses Direct3D 8 for graphics. Modern Macs and browsers cannot run it directly.

The end goal

You open a web page. You give the page your own copy of the game files. The game starts and you can play it. Nothing gets installed.
  • Platform: any modern browser with WebGPU.
  • Bring your own files (BYO): the player supplies the game files. We never host or share them.
  • Free and open source: no money, credit to LEGO and the original makers.
  • Faithful: the port must act like the original. We prove this with tests, not by feel.

Why not just emulate it?

An emulator is a fake old computer inside your new computer. It works, but it is slow. We tried it. The game moved like a slideshow.

We tested the original game under Boxedwine on an M1 Pro Mac. It ran at about 8 frames per second. A browser version of the emulator is slower still. So we chose a different route: rebuild the game engine in modern C++.

The rebuild copies the original behaviour. We read the original program as data to learn how it works. Then we write new code that does the same thing.

The route, step by step

  1. M0 Foundations. Tools, build system, and a readable decompile of the game program (5,618 functions).
  2. M1 Read and draw. Read the game's files and draw its areas in the browser. Done: you can test the area viewer today.
  3. M2 Scripts and menu. Run the game's own script language, then show the real main menu. In progress (M2a-2 almost closed).
  4. M3 One playable area. Walk, collide, talk, solve one area's puzzles.
  5. M4 Sound, cutscenes, saves.
  6. M5 The full game.
  7. M6 Release. Only with the owner's yes on licence, hosting and the public repo.

Where we are (2026-10-09)

The engine can open every game file and draw the world. Now it is learning to run the game's own little programs, the "scripts". That part is almost done. Then comes the menu, then the first playable level.
  • About 17 % of the whole road is done (board estimate).
  • The script engine runs 541 of 541 test programs. Two independent engines give identical results.
  • 69 game functions that the scripts call are rebuilt. On the real menu script, 600 frames match exactly between the native build, the browser build and a second reference engine.
  • Work is paused. Everything is saved in a private GitHub repo with a resume kit.

Words to know

Port
The same program, made to run on a new platform.
Engine
The code that runs a game: drawing, physics, sound, scripts.
WebAssembly
Fast compiled code that a browser can run. Short name: wasm.
WebGPU
The modern browser interface for the graphics card.
BYO
Bring your own. The player supplies the game files.
Milestone
One big step with a clear test at its end (M0, M1, M2 …).

Check yourself

Why do we not ship the game files with the port?

The files belong to LEGO. We ship only our own code. Each player supplies a copy they have.

Why did emulation lose?

It ran at about 8 frames per second on a fast Mac. A browser would be slower. A rebuild can run at full speed.

What does "faithful" mean here?

The port must do the same thing as the original in the same situation. We prove it with tests that compare against the original program's logic.
