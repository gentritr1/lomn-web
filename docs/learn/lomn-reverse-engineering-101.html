Reverse Engineering 101

How we learn what an old program does when nobody has its source code.

What reverse engineering is

Someone baked a cake and lost the recipe. You taste the cake, look at its layers, and write the recipe again. Reverse engineering is that, for programs.

A programmer writes source code in a language like C++. A compiler turns it into machine code: the numbers a processor runs. The source code of LOMN is lost. We only have the machine code, in LEGOBionicle.exe.

Reverse engineering (RE) reads that machine code and works out the logic. We then write new source code with the same logic.

Inside an .exe file

An .exe is a box with labelled drawers. One drawer holds the instructions. One holds numbers and words. One holds a list of help the program asks Windows for.

Windows programs use the PE format (Portable Executable). Its main parts are sections:

  • .text: the machine code.
  • .data and .rdata: numbers, text and tables. Example: the game's fixed time step lives here as a number, 1/150 s.
  • Imports: the Windows functions the game calls. LOMN imports 117 functions from 16 DLLs. Our port must replace all of them.

Every byte has an address, written in hexadecimal, like 0x4ff93e. We cite these addresses for every claim.

Assembly in one minute

Machine code is very small steps. "Put this number here." "Add these two." "If they match, jump over there." Thousands of tiny steps make one game action.

Assembly is machine code written as short words, for people. The game uses 32-bit x86. One instruction does one small job:

InstructionMeaning
cmp a, bCompare two values.
jne targetIf they were not equal, continue at target.
call fRun function f, then come back.
retReturn from the function. This marks a real function end.

Our lucky break: debug symbols

Usually a program has no labels inside. This one forgot to remove its labels. So we know the real names of most parts. It is like finding the cake recipe's chapter titles.

The build kept its CodeView NB11 debug information (Microsoft Visual C++ 6, built 2001-10-22). That block is 2.17 MB. It holds 7,057 names, 505 classes and about 4,800 type records.

So we see names like GcAreaLoader::LoadArea instead of FUN_004fedd0. This makes the work much faster and safer.

Ghidra

Ghidra is a big magnifying glass for programs. It turns the tiny steps back into something that looks like normal code. It is a guess, but a very good one.

Ghidra is a free RE tool from the NSA (we use version 12.1.4). Its decompiler turns machine code into C-like code. We run it headless (with no window) in a fixed pipeline:

  1. Import the .exe and apply the debug names and types.
  2. Let Ghidra analyse the code.
  3. Apply local variable names and the Direct3D 8 types.
  4. Export every function to a readable corpus (5,618 functions).

Ghidra output is a hint, not a fact.

Example from this project: Ghidra said LoadArea was 7,431 bytes long. The real function runs to its ret at 0x500fe4. A count that trusted Ghidra missed a third error-catch block. Now we always take function ends from the bytes.

Our safety rules

  • Never run the game's .exe or any DLL on our machines. We read them as data only.
  • Never commit game files, decompiled code blocks or disassembly listings to our repo. Short cited addresses are fine.
  • Cite everything. Every rebuilt behaviour names the address it comes from.
  • The player's game folder is read-only. Our tools refuse to write into it.

Words to know

Source code
The text a programmer writes.
Machine code
The numbers a processor runs.
Compiler
Turns source code into machine code.
Decompiler
Turns machine code back into source-like code. The result is approximate.
Disassembler
Shows machine code as assembly words. The result is exact.
Address
The position of a byte in the program, in hex.
Hexadecimal
Base-16 numbers: 0–9 then a–f. 0x10 = 16.
Debug symbols
Names and types left in a program by its build.

Check yourself

Why is a disassembler "exact" but a decompiler not?

A disassembler only renames each instruction. A decompiler must guess loops, variables and function borders. Guesses can be wrong.

Why do we never run the original .exe?

Safety and law. It is old code with mods we did not write. Reading it as data is enough and it cannot harm the machine.

What made this project possible at all?

The leftover debug symbols. They gave real names to most functions and classes.
