How We Know It Is Right

We cannot run the original game to compare. So we use tests that do not trust any single source.

The oracle

You and a friend do the same maths homework alone. Then you compare answers. If an answer is different, one of you made a mistake. Our "friend" is a second engine, written separately.

An oracle is something that tells you the correct answer. We have no running original, so we build a second implementation in Python. Different people (different agents) write the C++ side and the Python side. Neither reads the other's code.

Then we run both on the same input and compare every line of output. This is differential testing.

The conformance corpus

We wrote 541 tiny test programs. Each one checks one rule of the script machine. Both engines must pass every one, and their step-by-step notes must be the same, letter for letter.

Each program says what the correct result is. Both runners check it. They also write a trace: a log of every step. We compare the traces byte for byte.

Current result: 541 of 541 pass, and 541 of 541 traces are identical.

The runners fail closed: if a program has a field that no runner checks, the test fails. This rule once exposed a C++ check that had never run.

The real-script test (osi-a9)

We run the game's real menu script for 600 frames, four ways:

  1. the native Mac build;
  2. the browser (wasm32) build;
  3. the Python engine, replaying the C++ engine's native answers;
  4. the Python engine with its own native models.

All four must agree on all 601 lines. Today they do.

Agreement is not proof

If you and your friend learned the same wrong rule from the same book, you both get the same wrong answer. Comparing does not catch it. You need a third person who reads the real source.

This happened several times. Both sides agreed, and both were wrong, because both read the original the same wrong way:

  • four-letter codes stored with their bytes swapped;
  • a number parser that should clip large values, not wrap them;
  • an area-loading event. Both sides fired it for the wrong objects. The binary at 0x544065 shows it fires only for one object type.

Our rule now: every modelled constant and branch needs its own citation from the binary. For tricky paths, a third reader checks the bytes.

How a change gets accepted

  1. Write the test first. Show that it fails on the old code.
  2. Change the code. Show that the test now passes.
  3. A blind reviewer checks the change against the binary.
  4. Fix what the review finds. Review the fix.
  5. Merge. Run the full set again: conformance, osi-a9, all tool tests, both builds.
  6. The controller re-runs the checks itself. A report that says "all green" is not evidence.

Words to know

Oracle
A trusted source of correct answers.
Differential test
Run two versions on the same input and compare.
Trace
A step-by-step log of a run.
Fail closed
When unsure, fail the test instead of passing it.
Mutant
A copy of the code with one deliberate bug.
Shared misreading
Two "independent" sides that make the same mistake.

Check yourself

Both engines agree on every line. Is the port correct?

Not for sure. Both could share one misreading. Agreement proves consistency. Citations from the binary prove correctness.

Why must a new test fail before the fix?

A test that never failed may not test the bug at all. Seeing it fail proves it checks the broken path.

What does mutation testing measure?

The strength of the tests. If a deliberate bug survives, the tests have a blind spot.
